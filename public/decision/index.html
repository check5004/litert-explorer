03 · LEARNED SEMANTIC ROUTING · CPU ONLY

架空の問い合わせを、意味の近さで比較する

MediaPipe Tasks → LiteRT-LM → LiteRT

学習済みの埋め込み＋意味的なスコアリングです。生成された推論説明でも、問い合わせ分類専用に学習した decision head でもありません。

この実験で共有したいこと

学ぶ：学習済みモデルの意味表現を使い、候補の説明文に対する相対的なスコアを返す API を観察します。低水準の Tensor API と、業務に近い Tasks API の違いを比較できます。

業務の入口：問い合わせを端末内で仮分類し、担当者が確認してから振り分ける用途。曖昧な問い合わせや候補の定義変更で出力が変わることも確認してください。

実行経路：@mediapipe/tasks-decision 1.1.0 → LiteRT-LM → LiteRT / CPU・WASM。ホームの @litertjs/core とは異なる高水準 SDK です。

通信とデータ

入力は固定の架空例だけです。自由入力やファイルの読込はありません。SDK・WASM・モデルをこのページと同じオリジンから読み込みます。

SDK 1.1.0 は約 60 秒後の定期処理や close() 時に Google の指標エンドポイント（odml.pa.googleapis.com/v1/log）へ POST を試みます。このページは SDK の読込前に通信ガードを設置し、その送信を遮断します。CSP も外部接続を拒否します。SDK のオプトアウト機能ではありません。

この追加実験の資産は、ホームの「必要なファイルを保存」の対象外です。

ログは安全な送信先の origin/path・method と許可／遮断件数だけを記録し、本文・ヘッダー・API キーは記録しません。ガードの件数は通信の試行数で、ブラウザー全体のネットワーク監査ではありません。
