DECISION MAKER

問い合わせを、意味で振り分ける。

日本語の架空例を使い、学習済みモデルの相対スコアを観察します。

この実験で共有したいこと

学ぶ：学習済みモデルの意味表現を使い、候補の説明文に対する相対的なスコアを返す API を観察します。低水準の Tensor API と、業務に近い Tasks API の違いを比較できます。

業務の入口：問い合わせを端末内で仮分類し、担当者が確認してから振り分ける用途。曖昧な問い合わせや候補の定義変更で出力が変わることも確認してください。

実行経路：@mediapipe/tasks-decision 1.1.0 → LiteRT-LM → LiteRT / CPU・WASM。タブ 01・02 の @litertjs/core とは異なる高水準 SDK です。

通信とデータ

入力は固定の架空例だけです。自由入力やファイルの読込はありません。SDK・WASM・モデルをこのページと同じオリジンから読み込みます。

SDK 1.1.0 は約 60 秒後の定期処理や close() 時に Google の指標エンドポイント（odml.pa.googleapis.com/v1/log）へ POST を試みます。このページは SDK の読込前に通信ガードを設置し、その送信を遮断します。共通シェルの CSP は LLM 用の固定配信元を許可しますが、この Decision Worker は SDK より先に導入する完全一致の許可リストで、それ以外の通信を遮断します。Worker は共通 CSP を継承し、自己オリジン限定の CSP ではありません。SDK のオプトアウト機能ではありません。

この実験の資産は、共通シェルの「必要なファイルを保存」の対象外です。タブを離れると Worker は終了し、戻ったときもボタンでの再初期化が必要です。

ログは安全な送信先の origin/path・method と許可／遮断件数だけを記録し、本文・ヘッダー・API キーは記録しません。ガードの件数は通信の試行数で、ブラウザー全体のネットワーク監査ではありません。
